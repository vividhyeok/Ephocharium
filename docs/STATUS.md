# 개발 및 검증 현황

작성일: 2026-10-24 (한국 시간). 버전 0.1.

## UI 개선 반영

- 청록색과 샴페인 골드를 중심으로 헤더·도구·국가 정보·생성 및 저장 패널을 재설계했습니다. 도구는 Lucide 선형 아이콘으로 통일하고, 지도 위에 떠 있는 패널로 배치했습니다.
- 실제 국가를 선택하고 수도로 이동하는 왕국 목록, 클릭/키보드로 이동하는 미니맵, 확대·축소·전체 보기 버튼을 추가했습니다.
- 바다·해안·평야·숲·산·건물의 픽셀 표현과 국경 색감을 조정했습니다. 세계 생성 프리셋에는 코드로 그린 지도 일러스트를 넣었습니다. 일러스트는 장식용이며 생성될 시드 지도의 정확한 미리보기는 아닙니다.
- 모바일 배치, 버튼의 접근성 이름, 모달 포커스 제한·복원, 동작 줄이기 설정 대응을 개선했습니다.
- 프로덕션 빌드 및 브라우저 테스트 **6개 통과**. 기존 5개 흐름에 왕국 목록·미니맵·줌 버튼·패널 키보드 탐색 검증을 추가했습니다.
- UI 개선 후 동일한 250년 세계에서 120프레임 측정: 평균 **19.3ms**, 95백분위 **33.3ms**(이 PC의 Chromium). 초기 디자인에서 성능을 저하시키던 프레임별 지도 그림자와 패널 배경 블러는 제거했습니다. 기기·실행 부하에 따라 달라집니다.
- 개선 후 빌드: 메인 JS 약 276KB / gzip 약 89KB, CSS 약 25KB / gzip 약 6.3KB. 아래 최초 버전의 측정값과 구분합니다.

## 구현된 범위

- TypeScript·Vite·React·Zustand UI. 시뮬레이션은 Web Worker로 분리.
- 시드·지도 크기·바다·숲·산 설정. 바다·모래·평야·숲·산·눈 지형. 여섯 프리셋.
- 인간 배치 → 정착 대기 → 국가 형성 → 인구 성장 → 영토 확장.
- 지형별 생산성, 식량 생산·소비, 수용 인구, 자원 수입, 재산, 기술, 지도자 교체와 성향.
- 접경 관계, 평화 시 교역 보너스와 기술 전파, 조건부 전쟁, 타일 정복, 휴전, 행정 부담에 따른 독립, 멸망.
- 관찰·인간·인구 지원·생명 제거, 평야·바다·산·숲 브러시, 비·자원, 화재·운석·전염병·홍수, 왕국 생성·축복·전쟁·평화·반란·정복 방지 보호. 모든 표시 도구가 엔진 상태를 변경하거나 실제 정보 조회를 수행.
- 국경·농경지·건물·깃발·장식 주민·재해 효과. 카메라 확대·이동, 브러시 크기와 연속 적용.
- 한국어 튜토리얼·도구 설명·국가 패널·역사·멸망 국가 목록. 인구·영토 시계열은 상세 정보에 최근 표본을 표시.
- 일시정지와 고정 1/2/5/10/20배속. 관찰 모드 및 선택적 사건 위치 따라가기.
- IndexedDB 자동 저장, 수동 슬롯 3개, 삭제·불러오기, 파일 입출력과 중첩 데이터 검증. 세계·지형·국가·관계·이력·RNG 상태 보존.

## 아직 구현되지 않았거나 단순화된 범위

이번 버전을 전체 요구사항의 완성판으로 보아서는 안 됩니다.

- 독립 마을/도시 객체와 도시별 주거·건설 대기열이 없습니다. 현재 건물·농장은 영토와 연동된 시각적 표현이며 독립 경제 주체가 아닙니다.
- 주민 경로 탐색·직업·이주·가축·야생동물, 실제 이동 군대·보급선, 함대·항구·해상 교역, 별도 문화 체계가 없습니다. 군사 결과는 인구·기술·안정성·영토 규모로 집계 계산합니다. 산과 바다는 확장을 막지만 세밀한 지형별 전투 보정은 없습니다.
- 동맹은 접경 관계와 교역으로 단순화했습니다. 별도 동맹 조약·공동 참전·외교 협상·기억 모델은 후속 작업입니다. 합병은 영토 정복과 멸망의 결과로 발생하며 독립적인 평화 합병 의사결정은 없습니다.
- 강·호수 전용 생성기, 사막·복합 기후·계절·기온 조절, 광물 유형과 채굴 시설이 없습니다. 현재 자원은 지형 수입과 직접 지원으로 단순화했습니다.
- 번개·눈·토네이도·지진·화산·폭발·가뭄 등은 없습니다. 표시된 재해만 사용 가능합니다. 전염병은 단발 인구 피해이며 전염 경로 모델은 없습니다. 지형 피해는 시간에 따라 회복하는 단순 모델입니다.
- 시대별 건물 아트·선박·정교한 전투 애니메이션·음향·접근성 키보드 지도 탐색은 남아 있습니다.
- 지도·역사 렌더링 LOD를 일부 적용했지만 청크·공간 인덱스·부분 스냅샷 전송·동적 최대 안정 배속은 아직 없습니다.
- 세계 기록은 최근 1,200개 주요 사건, 국가 표본은 최근 150개로 제한합니다. 전체 역사 무제한 아카이브와 그래프·과거 패권국 전용 뷰는 없습니다. 자동 카메라는 사건 위치로 즉시 이동합니다.
- 터치 핀치 줌, 슬롯 덮어쓰기 취소/휴지통, 저장 실패 복구 UI는 추가 개선 대상입니다.
- 장기 균형은 초기 단계입니다. 분열을 지나치게 유도하던 행정 부담을 조정했지만 일부 시드에서 독립이 자주 생기거나 후반 전쟁이 잦을 수 있습니다. 여러 시간의 실제 관찰 플레이를 완료했다고 주장하지 않습니다.
- 오프라인 재접속, 클라우드 동기화, 멀티플레이는 없습니다.

## 실제 검증

환경: Windows, Node.js 24.11.0, Playwright Chromium, 데스크톱 1440×1000 및 모바일 390×844.

### 엔진: Vitest 11개 통과

| 명세 | 검증 |
| --- | --- |
| A | 인간 20명 배치 후 국가와 인구 증가 |
| B | 650년간 네 왕국의 영토 증가, 관계 변화, 전쟁 기록 |
| C | 지원한 세계와 대조 세계의 실제 인구·식량 및 80년 후 성장 경로 차이 |
| D | 큰 제국의 실제 안정성 하락·독립, 높은 기술의 행정 부담 완화 |
| E | 화재의 인구·지형 피해와 이후 피해 회복·문명 생존 |
| F | 같은 시드·동일 명령의 동일 결과, 다른 시드의 다른 인구 결과 |
| G | 2,000년 실행 후 유한한 상태·기록 상한·저장 데이터 유효성 |
| H | JSON 저장·복원 후 RNG를 포함한 상태 및 이후 80년 결과 완전 일치 |

추가: 여섯 프리셋 유효성, 바다 정착 거부, 손상된 중첩 저장 파일 거부.

### 브라우저: Playwright

- 세계 로딩, 일시정지·키보드 배속·20배속, 빈 세계 생성, IndexedDB 저장 슬롯·불러오기, 파일 다운로드, 관찰 모드 전환.
- 모바일 레이아웃·세계 생성 설정·재해 도구 및 가로 넘침 없음.
- 잘못된 세계 파일의 거부와 기존 지도 유지.
- 250년 성장한 실제 엔진 세계를 파일로 불러온 뒤 지도에서 국가 선택, 인구 지원으로 표시 인구 100명 증가.
- 15초 자동 저장 후 새로고침하여 같은 시점의 세계 복원.

단위 테스트는 전체 게임의 재미를 증명하지 않습니다. 브라우저 검증도 짧은 실제 조작 흐름과 캡처 확인이며, 장시간의 재미·다양한 저사양 기기·실제 휴대전화 성능은 추가 검증해야 합니다.

### 성능 측정

- 112×73 = 8,176개 타일, 시드 91, 전쟁 프리셋, 2,000년 계산: 약 **2.60초**, 평균 **1.30ms/년**. Node에서 엔진만 측정했으며 브라우저 전송·그리기는 제외합니다.
- 해당 실행 종료 시 54개 역사적 국가 중 47개 생존, 전체 인구 약 213,488명. 결과를 보장하는 고정 이벤트는 아닙니다.
- 250년 세계를 불러와 확대한 브라우저의 120프레임: 평균 **16.5ms**, 95백분위 **16.7ms**, 약 60fps. 이 PC의 짧은 측정이며 장시간·저사양 성능 보장은 아닙니다.
- 프로덕션 빌드: 메인 JS 약 254KB / gzip 약 81KB, Worker 약 13KB, CSS 약 11.5KB. 사용하지 않는 PixiJS는 제거했습니다.
- `npm audit`: 취약점 0개. 초기 Vitest 의존성의 취약점을 확인해 최신 버전으로 갱신했습니다.

## 배포 현황

- 대상 저장소: https://github.com/vividhyeok/Ephocharium
- Vercel 설정: Vite, `npm ci`, `npm run build`, 출력 `dist`.
- 연결된 Vercel의 기본 팀에 접근하려는 요청이 403으로 거부되었습니다. 도구가 발급한 팀 접근 승인 링크로 사용자 인증이 필요합니다. 배포·자동 Git 연결·운영 URL 접속 검증은 아직 완료되지 않았습니다.
- 원격 배포 URL: 없음. 로컬 테스트 성공과 원격 배포 성공을 구분합니다.
- `.github/workflows/checks.yml`은 푸시/PR 시 Node 24에서 엔진·빌드·브라우저 검증을 수행하도록 설정했습니다. 로컬 성공과 GitHub Actions 원격 실행 결과는 별개입니다.

## 다음 개발 순서

1. 독립 정착지·주거·건설·도시 모델을 도입하고 지도 표현과 연결.
2. 교역 경로·이주·국가별 기술 분화, 군대·보급·지형 방어를 구현.
3. 강·기후·해상 이동 및 나머지 신의 능력 확장.
4. 여러 시드와 장시간 관찰을 통한 인구·분열·전쟁 빈도 균형 조정.
5. 시대별 픽셀아트·모바일 조작·접근성·대형 지도 최적화.
6. Vercel 권한 승인 후 Git 연결·배포·실제 운영 URL 검증.
